# Release conditions for assistant knowledge grants

Version `v2.10.0-rc.4` adds the grant table. It does **not** assign legacy snippets to an assistant. After cutover, an empty selection means no snippet access, even if an assistant previously returned that content. Staff Copilot and Generate Reply no longer search snippets; Help Center articles are not grantable.

| Stage                   | Required condition                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before the upgrade      | Back up the database. Quiesce assistant replies, previews and staff AI requests on **all** instances; drain queued work and pending tool approvals. Legacy readers ignore grants, so a mixed-version serving pool is unsafe.                                                                                                                                            |
| Schema check            | Apply the registered migration before starting binaries that prepare scoped SQL. Verify `ai_assistant_knowledge_items`, its composite PK and both cascading FKs, and `index_ai_assistant_knowledge_items_on_item`. Immediately after first migration there must be zero grant rows. Investigate unexpected grants rather than clearing or accepting them automatically. |
| Before resuming traffic | Verify every serving instance and worker enforces scoped retrieval. In a disposable environment, verify unbound denial, explicit assignment, preview/live isolation, revocation on the next search, and staff search denial. Do not treat a passing UI check as proof of worker isolation.                                                                              |
| Grant administration    | Authorized administrators explicitly replace the selected set for an assistant. Verify the assistant primary key, not its paired user ID. Audit the actor, assistant and ID changes; do not use query/payload logging to validate assignments. No vector rebuild is required.                                                                                           |
| Rollback                | Keep the additive schema, grants, and vectors. Stop affected traffic and workers or use a version that still enforces the grants. Do not restore a globally searching binary and resume AI traffic against the same content.                                                                                                                                            |

Content selection, provider configuration and production execution are separate operational decisions.
